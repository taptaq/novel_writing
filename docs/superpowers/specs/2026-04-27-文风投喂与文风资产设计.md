# 文风投喂与文风资产设计

日期：2026-04-27

范围：
- `新建书籍` 增加可选的参考样文输入
- 新增书籍级 `文风资产` 与 `文风投喂` 管理能力
- `续写` 与 `去 AI 味改写` 接入书籍级文风记忆
- 为上述能力补充数据结构、接口与异常处理

目标：
- 让 `humanize-novel-prose` 技能在项目中从一次性改写升级为可持续复用的文风系统
- 让用户可以在建书时低成本提供参考样文，但不被强制填写
- 让同一本书的 `续写` 和 `改写` 能稳定贴合既定 voice，而不是每次只走通用规则
- 保持主写作界面简洁，把重度文风管理收进独立入口

## 1. 设计方向

本期采用：
- `独立文风资产层`
- `创建可选填 + 后续独立追加`
- `自动提炼 + 用户可见可编辑`
- `默认生效，必要时可临时关闭`

不采用：
- 继续把文风信息零散塞进 `Novel` 的普通字段
- 在主编辑器里堆大量文风配置项
- 首期就做完整历史版本、差异对比、角色级专属文风引擎

核心理念：
- 文风素材与文风规则要分开存
- AI 实际消费的是“当前生效的文风资产”，不是原始样文堆
- 用户看得到、改得动，但普通写作流程不应被打断

## 2. 信息架构

本期涉及三个入口：

- `新建书籍页`
  - 新增 `文风参考（选填）` 分区
  - 支持用户在创建时直接粘贴少量参考样文
- `书籍内文风页`
  - 作为独立 `文风投喂 / 文风资产` 页面
  - 用于追加样文、停用样文、查看与编辑提炼结果
- `章节编辑页`
  - 不新增复杂区块
  - 只展示当前文风已生效的轻提示，并允许本次临时关闭

工作流：

1. 用户在创建作品时可选填参考样文
2. 进入作品后可继续在独立文风页追加素材
3. 系统根据启用中的样文提炼结构化文风资产
4. 用户可手动修改文风摘要与规则
5. `续写` 与 `去 AI 味改写` 默认读取当前生效的文风资产

## 3. 数据模型设计

### 3.1 新增文风资产主表

建议新增 `NovelStyleProfile`，一书一份。

职责：
- 存当前书籍已经整理好的、可直接供模型消费的文风资产
- 存用户手动修订后的最终生效版本

建议字段：
- `id`
- `novelId`
- `styleSummary`：一句话概括当前作品文风
- `styleRules`：正向规则列表
- `avoidRules`：负向规则列表
- `dialogueRules`：对白表达规则
- `narrationRules`：叙述规则
- `rhythmRules`：节奏与停顿偏好
- `imageryRules`：常见意象或感知偏好
- `status`：如 `EMPTY`、`READY`、`FAILED`
- `lastGeneratedAt`
- `createdAt`
- `updatedAt`

说明：
- 结构化数组优于单个长文本，更利于提示词拼装和手动编辑
- 最终 AI 使用的始终是这里的内容，而不是直接消费样文全文

### 3.2 新增文风样文表

建议新增 `NovelStyleSample`，一书多条。

职责：
- 存放原始投喂素材
- 支持持续追加、停用、重提炼

建议字段：
- `id`
- `novelId`
- `title`
- `sourceType`：如 `USER_SAMPLE`、`EXISTING_CHAPTER`、`MANUAL_PASTE`
- `content`
- `note`
- `isActive`
- `createdAt`
- `updatedAt`

说明：
- `isActive` 用于控制某段样文是否参与当前提炼
- 首版不做复杂版本系统，但保留素材级开关，已经足够支撑重提炼

### 3.3 `Novel` 创建链路扩展

`NovelCreationInput` 需要新增可选字段，例如：
- `styleSamples?: Array<{ title?: string; content: string; note?: string }>`

设计要求：
- 创建时完全可不填
- 若填写，则创建完成后自动初始化 `NovelStyleSample`
- 若至少存在有效样文，可同步触发一次初始提炼

## 4. 页面与交互设计

### 4.1 新建书籍页

在现有创建表单中新增 `文风参考（选填）` 分区。

交互要求：
- 默认文案明确告诉用户“可先跳过，后续仍可补充”
- 支持录入 `1 到 3` 段参考样文即可，不做无限追加
- 每段包含：
  - `标题 / 来源` 可选
  - `样文正文` 必填
  - `备注` 可选

设计原则：
- 这是增强项，不是拦路项
- 不做过多教育文案，避免表单再次变重

### 4.2 独立文风页

建议新增一页，统一承接：
- 查看当前文风摘要
- 编辑结构化规则
- 追加样文
- 停用或启用样文
- 触发重新提炼

页面可分为两区：

`上半区：当前文风资产`
- 文风概述
- 正向规则
- 避免表达
- 对白规则
- 叙述规则

`下半区：投喂素材`
- 样文列表
- 启用状态
- 标题 / 备注
- 新增样文入口
- 重新提炼按钮

设计原则：
- 允许用户直接改规则，不必每次都重新投喂
- 文风资产和样文素材清晰分层，避免混在一块造成理解负担

### 4.3 章节编辑页

主写作页保持简洁，不新增复杂配置表单。

建议交互：
- 在 AI 面板中新增轻量提示：`当前已应用文风资产`
- 提供一个本次请求级别的临时开关：`本次不使用文风约束`
- 不在主页面内展示大段文风规则详情
- 若用户要查看或编辑规则，引导去独立文风页

## 5. AI 工作流设计

### 5.1 总体流程

文风能力采用以下闭环：

1. `投喂`
2. `提炼`
3. `人工修订`
4. `写作生效`

### 5.2 提炼流程

后端根据当前启用中的样文，输出结构化文风资产。

提炼目标不是生成一篇风格分析长文，而是提炼出可复用规则，例如：
- 叙事距离与视角贴近度
- 句法节奏与停顿偏好
- 对白口吻特征
- 常见意象或感官习惯
- 明确应避免的表达方式

提炼结果回写到 `NovelStyleProfile`。

### 5.3 `续写` 模式接入

`continue` 模式除现有上下文外，还需带入：
- 文风概述
- 正向规则
- 禁忌规则
- 对白 / 叙述重点

目标：
- 让生成文本更像“这本书会写出来的话”
- 避免不同书共用一套平均化的语气

### 5.4 `去 AI 味改写` 模式接入

`rewrite` 模式在现有去 AI 味规则之外，还需额外遵循当前作品文风资产。

目标：
- 不只是把句子改顺
- 而是改成“更像这本书自己的写法”

### 5.5 临时关闭文风约束

为了保留灵活性，每次 AI 请求应允许用户临时关闭文风约束。

适用场景：
- 当前只是想做结构建议，不强调 voice
- 当前章节故意切换叙事温度
- 用户怀疑文风资产已经偏了，想做一次对照

说明：
- 这是请求级开关，不改变持久化配置

## 6. 异常处理

### 6.1 无样文

若当前书籍没有任何有效样文：
- 不报错
- 文风资产可为空
- `续写` 与 `改写` 退回通用去 AI 味规则

### 6.2 样文过短或质量不足

若样文内容不足以稳定提炼：
- 给出轻提示
- 不阻止保存样文
- 允许用户手动编辑文风规则

### 6.3 提炼失败

若模型提炼失败或返回异常：
- 保留原有 `NovelStyleProfile`
- 不使用失败结果覆盖旧内容
- 页面提示用户稍后重试

### 6.4 人工修改优先级

用户手动保存后的文风资产优先级高于自动提炼稿。

原则：
- 自动提炼是草稿
- 用户修订版才是当前生效版本

## 7. 首版边界

本期明确包含：
- 创建时可选填样文
- 独立文风页
- 文风资产结构化存储
- `续写` / `改写` 接入文风资产
- 请求级临时关闭文风约束

本期明确不包含：
- 多版本文风资产回滚
- 样文差异对比
- 角色级专属文风模型
- `audit` 模式的深度风格诊断
- 基于既有章节自动批量反推整本书文风

## 8. 测试与验收

验收标准：
- 新建书籍时可以不填样文并成功创建
- 新建书籍时填写样文后能成功落库
- 书籍内可查看与编辑文风资产
- 可在独立文风页追加样文并重新提炼
- `续写` 和 `改写` 请求能稳定读取当前文风资产
- 未配置文风资产时，现有 AI 功能不回归、不报错

建议测试覆盖：
- 表单校验与空值处理
- 文风样文 CRUD
- 文风提炼结果持久化
- AI prompt 拼装是否正确带入文风资产
- 临时关闭文风约束时是否正确降级

## 9. 实施顺序建议

建议按以下顺序实现：

1. 数据模型与 Prisma schema
2. 创建链路扩展
3. 独立文风页与基础 CRUD
4. 文风提炼接口
5. `续写` / `改写` prompt 接入
6. 验证无文风资产时的回退行为

## 10. 风险与控制

主要风险：
- 样文质量不稳定导致提炼结果飘
- 主编辑页若塞入太多文风说明，会再次变重
- 自动提炼若直接覆盖人工修改，用户会失去控制感

控制策略：
- 样文与文风资产分层
- 编辑器只保留轻提示
- 人工修订结果优先
- 提炼失败不覆盖旧结果
