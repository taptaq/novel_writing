# 人物关系图与 PNG 导出设计

日期：2026-04-27

范围：
- 将 `/novels/[novelSlug]/graph` 从静态列表页升级为可交互关系图工作台
- 支持按实体范围切换图谱视图
- 支持点击节点后的关系高亮与详情联动
- 支持导出“当前视图”为 PNG 图片
- 为关系详情补齐 `description / remark / note` 的结构化数据读取能力

目标：
- 让图谱页从“列出实体与关系”升级为“真正可用的关系梳理工具”
- 默认先给用户一个干净的人物关系视图，再按需扩展到势力与地点
- 让用户能快速完成三件事：`看图`、`点图`、`导图`
- 保持主流程简洁，不把图谱页做成重型编辑器

## 1. 设计方向

本期采用：
- `图谱页内可交互关系图`
- `默认只看人物，可切换更多实体`
- `点击节点后双联动：画布高亮 + 右侧详情`
- `导出当前视图 PNG`
- `前端关系图库驱动，前端本地导出`

不采用：
- 服务端预渲染静态关系图作为主方案
- 首期就做图上直接编辑关系文案
- 首期就做复杂排版、持久化拖拽位置、多人协同
- 为导出单独做复杂弹窗或额外页面

核心理念：
- 图谱页优先解决“理解关系”，不是优先解决“编辑关系”
- 第一版先把交互路径做顺，不把功能做散
- 默认状态必须干净、轻量、能立即看懂

## 2. 页面结构

图谱页升级为三栏工作台：

- `左侧栏：筛选与操作`
  - 实体范围切换：
    - `人物`
    - `人物 + 势力`
    - `人物 + 势力 + 地点`
  - 图谱操作：
    - `导出当前关系图 PNG`
    - `重置视图`
- `中间栏：关系图画布`
  - 展示节点与连线
  - 支持点击节点、缩放、平移、重置
  - 默认展示人物图谱
- `右侧栏：详情面板`
  - 当前选中实体的名称、类型、简介
  - 当前实体的直接关系列表
  - 每条关系的说明、备注、附加说明

说明：
- 没有选中节点时，右侧展示“当前图谱概览”，包括节点数、关系数、当前筛选范围
- 选中节点后，右侧切换为该实体详情

## 3. 核心交互

### 3.1 默认视图

- 首次进入图谱页时默认使用 `人物`
- 若当前书没有人物但有其他实体，则自动退回到“全部可展示实体”
- 画布自动执行一次 `fit view`，保证首屏能完整看到主要节点

### 3.2 节点点击

点击任一节点后，页面立即发生两类联动：

- `画布联动`
  - 高亮当前节点
  - 高亮与其直接相连的节点与关系边
  - 其他非直接相关节点降权显示
- `详情联动`
  - 右侧展示该节点的基本信息
  - 列出它的直接关系
  - 每条关系同时展示目标对象与关系说明

### 3.3 实体范围切换

范围切换会影响：
- 画布中可见节点集合
- 可见关系边集合
- 右侧概览统计
- 导出 PNG 的最终内容

默认规则：
- `人物`：仅保留 `CHARACTER`
- `人物 + 势力`：保留 `CHARACTER / FACTION`
- `人物 + 势力 + 地点`：保留 `CHARACTER / FACTION / LOCATION`

如果当前选中节点在切换后被过滤掉：
- 自动清空当前选中状态
- 右侧恢复图谱概览

### 3.4 关系表现

第一版建议使用简单清晰的视觉编码：
- 当前选中节点：深色高亮
- 与选中节点直接相连的边：主强调色实线
- 非当前焦点关系：弱化颜色
- 间接线索或弱关联：如后续需要，可用虚线表示，但首版不强制复杂分类

## 4. 导出 PNG 设计

### 4.1 导出原则

导出内容为 `当前视图`，而不是固定模板图。

这意味着导出时会保留：
- 当前实体范围筛选
- 当前缩放与视口状态
- 当前选中节点与高亮关系

### 4.2 导出信息

PNG 中保留少量必要信息：
- 作品名
- 当前筛选范围
- 导出时间

不附加大段说明文字，避免图片再次变重。

### 4.3 导出入口

- 入口固定在左侧栏
- 不做复杂弹窗
- 点击后直接导出

### 4.4 技术路线

本期推荐：
- 图谱渲染使用图谱专用前端库
- 图谱导出直接调用前端当前画布的 PNG 导出能力

推荐实现：
- 使用 `cytoscape.js`
- 使用其内置布局能力生成关系图
- 使用其 `png()` 能力导出当前画布

选择理由：
- 更适合“实体关系图”，而不是流程图
- 节点、边、筛选、高亮能力成熟
- 自带导出 PNG 能力，和“导出当前视图”的要求天然一致

## 5. 数据模型设计

## 5.1 当前问题

当前关系创建链路里，`description / remark / note` 会在写入前被拼成一个 `description` 字段：

- `description`
- `备注：remark`
- `说明：note`

这会导致：
- 右侧详情无法分栏展示
- 后续关系编辑会很难拆回结构化数据
- 导出时只能输出混合说明，信息层次差

## 5.2 建议调整

建议把 `EntityRelation` 改为显式保留：
- `description`
- `remark`
- `note`

即数据库层新增：
- `remark String?`
- `note String?`

并同步调整：
- 关系创建写入逻辑
- 图谱读取逻辑
- 类型定义 `GraphEdgeSummary`
- 测试数据与 demo 数据

## 5.3 图谱读取结果

图谱页读取接口返回的边数据建议为：

```ts
type GraphEdgeSummary = {
  id: string;
  sourceId: string;
  targetId: string;
  type: GraphRelationKind;
  description?: string;
  remark?: string;
  note?: string;
};
```

这样可以支持：
- 右侧详情按信息层级展示
- 导出时按需拼装文案
- 后续如要补关系编辑，也不需要再返工拆字段

## 6. 技术实现建议

### 6.1 组件拆分

建议把图谱页拆成以下单元：

- `GraphWorkspace`
  - 客户端总控组件
  - 管理筛选状态、选中状态、导出动作
- `GraphFilterPanel`
  - 左侧实体范围切换与操作按钮
- `GraphCanvas`
  - 关系图画布
  - 负责节点点击、缩放、重置、导出
- `GraphDetailPanel`
  - 右侧概览 / 节点详情展示

这样可以避免把所有交互都塞进 `page.tsx`。

### 6.2 服务端与客户端边界

- `page.tsx` 继续负责服务端取数
- 图谱原始数据作为 props 传入客户端工作台
- 图谱筛选、选中、高亮、导出完全在客户端处理

这样能保持：
- 数据获取简单
- 交互延迟低
- 导出状态与当前界面一致

### 6.3 布局策略

第一版采用图库自带自动布局即可。

要求：
- 节点不要严重重叠
- 人物少时尽量居中分散
- 实体增多时保持基础可读

不要求：
- 首版就针对几十上百节点做高级布局优化
- 持久化用户手动拖拽后的坐标

## 7. 第一版边界

本期明确包含：
- 图谱页三栏工作台
- 关系图画布
- 默认人物视图
- 实体范围切换
- 点击节点后的高亮与详情联动
- 导出当前视图 PNG
- 关系边结构化字段补齐

本期明确不包含：
- 图上直接新增 / 删除节点
- 图上直接编辑关系文字
- 持久化节点位置
- 多选节点分析
- 图谱历史版本
- 分享链接、协作批注、打印版 PDF

## 8. 异常与空状态

### 8.1 无图谱数据

若当前书没有任何可展示实体：
- 画布展示空状态提示
- 左侧筛选保持可见但禁用
- 右侧展示“暂无人物图谱，可先去设定页补充实体”

### 8.2 有实体无关系

若有节点但没有边：
- 仍展示节点
- 右侧概览提示“当前还没有关系线”
- 导出仍可用

### 8.3 筛选后无结果

若当前筛选范围下没有节点：
- 画布展示“当前筛选下暂无实体”
- 提供恢复到更宽范围的引导

## 9. 测试方案

### 9.1 页面测试

验证图谱页能渲染：
- 左侧筛选与导出入口
- 中间关系图工作台容器
- 右侧详情面板

### 9.2 数据映射测试

验证图谱读取结果能保留：
- `description`
- `remark`
- `note`

同时验证筛选逻辑能正确裁剪：
- 节点集合
- 关系边集合

### 9.3 交互测试

验证：
- 默认筛选为 `人物`
- 切换筛选后可见节点变化
- 点击节点后选中状态变化
- 右侧详情同步更新

### 9.4 导出测试

验证：
- 导出按钮存在
- 导出动作使用当前筛选与当前选中状态
- 导出文件名包含作品标识与日期信息

## 10. 实施顺序建议

建议按以下顺序落地：

1. 补齐 `EntityRelation` 的 `remark / note` 结构化字段
2. 调整图谱读取与类型定义
3. 引入图谱前端库并完成工作台骨架
4. 接入筛选、选中、高亮逻辑
5. 接入 PNG 导出
6. 补齐页面与交互测试

这样做可以先把数据质量打好，再做前端关系图，不会在详情展示阶段返工。
