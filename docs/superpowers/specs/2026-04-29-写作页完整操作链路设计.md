# 写作页完整操作链路设计

## 1. 目标

把当前章节写作页从“能打开单章但操作链不完整”的状态，升级成一个真正可连续使用的写作工作台。

这次要补齐的核心问题只有 5 个：

1. 顶部 3 个占位按钮要变成真功能
2. 写作页里要能直接新建章节
3. 要有可切换的章节目录
4. 章节目录要支持收起，并记住上次状态
5. 不额外长出太重的新页面，尽量在当前写作页内把主流程闭环

## 2. 用户目标

用户进入任意一章后，应该可以在同一页面里完成下面这条主线：

1. 查看当前章节
2. 随时切到别的章节
3. 新建下一章
4. 写正文
5. 自动保存或手动立即保存
6. 对比当前草稿和最近一次保存版本
7. 快速查看和本章相关的人物、伏笔、大纲
8. 如有需要，再跳去设定页或图谱页深看

## 3. 本次选型结论

本次采用 `平衡型` 方案。

不是只补按钮，也不是一次把写作页做成超重编辑器，而是做成：

- 左侧：章节目录栏
- 中间：正文编辑区
- 右侧：本章信息与 AI 动作区

同时坚持两个边界：

- 不新增“本章上下文独立页”
- 不把图谱、设定、版本系统做成独立重工作台后再跳转

核心原则是：先把用户最常用的写作链路做顺，不为了“以后也许会用到”的复杂场景把当前页面做重。

## 4. 页面结构

### 4.1 整体布局

写作页改成三栏：

- 左侧 `章节目录栏`
- 中间 `正文编辑主区域`
- 右侧 `当前目标 / 前文记忆 / 人物与伏笔 / AI 动作`

当前右侧信息区的大方向保留，不再推翻，只补强左侧和中间工具区。

### 4.2 左侧章节目录栏

左侧目录栏默认展开，展示：

- 当前作品章节列表
- 当前所在章节高亮
- 章节标题
- 章节状态
- 章节字数
- `新建章节` 按钮

目录栏支持收起。

收起后的状态：

- 不完全消失
- 保留一条窄栏入口
- 用户可随时点开

状态记忆规则：

- 用户手动收起后，记录当前状态
- 下次再进入写作页时，保持上次的展开 / 收起状态
- 记忆范围以当前浏览器本地为准，不依赖数据库

推荐实现方式：

- 使用 `localStorage`
- key 采用稳定命名，例如：`chapter-sidebar:collapsed`

### 4.3 中间正文编辑区

中间主区域保留当前编辑定位：

- 章节标题
- 字数
- 状态
- 场景目标
- 正文输入框

正文上方工具条改成 3 个真实按钮：

- `立即保存`
- `版本 Diff`
- `相关设定`

同时补一个轻量保存状态提示：

- `保存中`
- `已保存`
- `保存失败`

### 4.4 右侧信息区

右侧继续沿用这次已经确定的顺序：

1. 本章目标
2. 前文记忆
3. 人物与伏笔
4. 本次要做什么
5. AI 输出

不在这次里继续重排。

## 5. 五个功能的具体定义

### 5.1 自动保存 + 手动立即保存

采用“双轨制”：

- 用户输入正文时自动静默保存
- 同时保留 `立即保存` 按钮

自动保存行为：

- 用户停止输入一小段时间后触发
- 只在正文实际发生变化时触发
- 保存成功后更新状态为 `已保存`
- 保存中显示 `保存中`
- 保存失败显示 `保存失败`

手动保存行为：

- 点击 `立即保存` 后立刻提交当前草稿
- 手动保存与自动保存共用同一条保存接口
- 成功后也写入版本记录

本次保存内容至少包括：

- `plainText`
- `wordCount`
- `updatedAt`
- 本次不改 `sceneGoal` 保存链路

### 5.2 版本 Diff

第一版采用最实用的范围：

- 默认对比 `当前草稿 vs 最近一次保存版本`
- 下方附带 `历史版本列表`

第一版不做“任意两版本自由对比”。

Diff 展示形态：

- 点击 `版本 Diff` 打开弹窗
- 弹窗顶部展示默认对比结果
- 弹窗下半区列出历史版本时间线

第一版明确采用 `分左右两栏 + 按段展示` 的方式，不做复杂逐字高亮。

第一版优先保证：

- 用户能看出哪里改了
- 能知道当前草稿和最近一次保存差异大不大

### 5.3 相关设定

采用轻弹窗方案。

点击 `相关设定` 后，在当前写作页内弹出一个 `本章相关设定` 弹窗，优先展示 3 类内容：

1. 相关人物
2. 当前未回收伏笔
3. 本章相关大纲

弹窗底部再提供两个跳转按钮：

- `打开设定页`
- `打开图谱页`

这样处理的原因：

- 大部分时候用户只想“看一眼”
- 少部分时候才需要深入跳走
- 弹窗比独立页面更不打断写作

### 5.4 新建章节

`新建章节` 放在左侧章节栏中，保证切章节和建章节在同一区域完成。

点击后行为：

1. 自动创建下一章
2. 自动计算 `order`
3. 自动生成默认标题
4. 自动生成唯一 `slug`
5. 创建成功后直接跳转到新章节写作页

默认标题统一为：

- `第 X 章`

### 5.5 章节目录切换

章节目录必须可直接切换，不需要先回总览页。

点击章节项后：

- 直接进入对应章节写作页
- 当前章节高亮切换
- 若当前草稿有未保存内容，需避免无提示丢失

这里需要一个明确策略：

- 若当前草稿已保存，直接切换
- 若当前有未保存改动，先尝试自动保存
- 自动保存成功后再切换
- 若保存失败，则阻止切换并提示用户

本次不做复杂的“离开确认弹窗”，优先保证链路顺。

## 6. 数据与接口调整

### 6.1 写作页数据扩展

当前 `getChapterEditorData()` 只返回当前章节所需数据，不足以支撑左侧目录和版本列表。

本次需要补到 `ChapterEditorData` 的内容：

- 当前作品全部章节摘要列表
- 当前章节历史版本摘要列表

推荐新增字段：

- `chapters: ChapterSummary[]`
- `versions: Array<{ id: string; createdAt: string; source: string; note?: string; wordCount: number }>`

当前已有 `NovelWorkspace` 里已经有章节列表逻辑，可以复用映射方式，减少重复。

### 6.2 新增接口

本次明确补 2 类接口：

1. `PATCH /api/novels/[novelSlug]/chapters/[chapterSlug]`
   - 保存章节正文
   - 同时写入 `ChapterVersion`

2. `POST /api/novels/[novelSlug]/chapters`
   - 新建章节

第一版不单独新增 diff 接口。

Diff 所需数据由写作页已有数据补齐：

- 当前草稿来自前端编辑态
- 最近一次保存版本内容通过章节详情数据一并返回
- 历史版本列表通过章节详情数据一并返回

### 6.3 版本写入规则

每次成功保存后：

- 更新 `Chapter.plainText`
- 更新 `Chapter.wordCount`
- 追加一条 `ChapterVersion`

为了避免版本爆炸，自动保存需要节流。

版本写入规则明确为：

- 手动保存：每次都写入一条 `ChapterVersion`
- 自动保存：仅在距离上一条自动保存版本超过设定时间窗口时写入新版本

第一版推荐时间窗口为 `60 秒`。

## 7. 交互细节

### 7.1 收起状态记忆

章节目录栏展开 / 收起状态保存在浏览器本地。

规则：

- 首次进入默认展开
- 用户手动切换后记忆
- 下次进入优先读取本地状态

### 7.2 保存状态文案

建议统一为：

- `保存中`
- `已保存`
- `保存失败`

避免用太技术化的话。

### 7.3 空状态

如果还没有任何章节：

- 左侧目录栏显示空状态
- 同时给出主按钮 `新建第一章`

如果版本列表为空：

- `版本 Diff` 弹窗里提示：`当前还没有保存版本，先保存一次再查看差异。`

如果本章没有明显相关设定：

- `相关设定` 弹窗里给轻提示，而不是空白

## 8. 错误处理

### 8.1 保存失败

- 不切章节
- 不静默吞掉错误
- 顶部状态显示 `保存失败`
- 保留当前编辑内容

### 8.2 新建章节失败

- 给出明确提示
- 不跳转
- 不清空当前页状态

### 8.3 相关设定为空

- 仍然打开弹窗
- 用人话说明“当前这章还没有明显关联的人物 / 伏笔 / 大纲”

## 9. 测试范围

本次至少要补这些测试：

1. Prisma / 仓储层
   - 可创建章节
   - 可保存章节
   - 可写入版本
   - 可返回章节列表
   - 可返回版本摘要

2. 写作页组件
   - 左侧目录栏渲染
   - 章节目录收起与展开
   - 保存状态文案
   - 新建章节按钮
   - `版本 Diff` 弹窗
   - `相关设定` 弹窗

3. API
   - 保存章节接口
   - 新建章节接口

4. 页面行为
   - 切章节时自动保存
   - 创建章节后跳到新章节
   - 收起状态记忆

## 10. 不在本次范围内

这次明确不做：

- 任意两历史版本自由比对
- 图谱内直接编辑
- 复杂富文本编辑器
- 独立“本章上下文页”
- 多人协作
- 章节拖拽排序

## 11. 为什么这样定

这套方案的核心价值不是“功能最多”，而是：

- 把写作页真正补成一个连续可用的主工作台
- 不逼用户频繁离开当前页
- 不为了未来场景把现在做成重编辑器

用户真正最常做的动作，本次都会被覆盖：

- 切章
- 建章
- 写
- 存
- 对比
- 查设定

这就足够把当前写作链路从“半成品”推进到“能长期用”的状态。
