# 首页与作品入口页 UI 精简化设计

日期：2026-04-26

范围：
- `src/app/page.tsx`
- `src/app/novels/page.tsx`
- `src/app/globals.css`

目标：
- 将首页和作品入口页从“解释型骨架页”收敛为“可快速进入的产品首页”
- 保留“未来编辑部感”，但去掉无关长文案和过多概念说明
- 让用户在 3 秒内理解产品用途，并明确下一步入口

## 1. 设计方向

本轮采用 `A / 状态型极简首页`。

整体气质为“未来编辑部感的轻信息产品首页”：
- 有产品感和系统感，但不过度科技化
- 有品牌气质，但不以理念宣言抢占注意力
- 用少量状态信息建立可信度，用明确入口推动用户进入工作区

不采用的方向：
- 不做高密度控制台式首页，避免信息压力过大
- 不做重品牌叙事首页，避免用户先读说明再找入口
- 不做世界观档案室风格，避免稀释“进入工作区”的主目标

## 2. 信息架构

首页保留三段结构：

1. 首屏 Hero
2. 轻量能力标签区
3. 最近作品入口区

作品入口页保留两段结构：

1. 简洁页头
2. 作品列表

删减原则：
- 移除或压缩大段解释性文案
- 不再单独保留“框架重点”式说明面板
- 不让同一屏同时承担“讲理念”和“讲功能”和“给入口”三件事

## 3. 首页设计

### 3.1 首屏 Hero

首屏只保留：
- 一句主标题
- 一行补充说明
- 两个 CTA
- 三个短状态卡

建议文案方向：
- 主标题：强调“AI 协作写作”而不是“AI 自动写作”
- 补充说明：一句话解释这是一个帮助作者推进结构、设定与章节的工作台
- 主 CTA：`进入示例工作区`
- 次 CTA：`查看作品`

文案规则：
- 标题不超过两行
- 补充说明控制在一行到两行
- 不使用长句解释“产品哲学”
- 避免出现连续三句以上的说明文案

### 3.2 状态卡

Hero 区配套三个状态卡：
- `结构`
- `设定`
- `写作`

每张卡只包含：
- 一个短标题
- 一个短状态短语
- 一条极短辅助信息

示例表达层级：
- `结构` / `节拍可追踪`
- `设定` / `实体可统一`
- `写作` / `上下文可接续`

状态卡作用：
- 不是介绍所有能力
- 只是用极少文字告诉用户“这个产品能管住哪些关键环节”

### 3.3 轻量能力标签区

保留一段非常短的能力概览，但改为标签式或短卡式表达。

形式要求：
- 每项只保留关键词级别说明
- 不出现段落说明
- 数量控制在 3 到 4 项

建议内容类型：
- `结构建议`
- `设定映射`
- `上下文续写`
- `风格护栏`

该区域的目的不是讲解，而是补充可信度和完整性。

### 3.4 最近作品入口区

该区域上移，成为首页最重要的下一个模块。

每张作品卡只显示：
- 标题
- 一句摘要或 premise
- 题材
- 章数
- 字数
- 明确可点击入口

交互原则：
- 用户无需先读完首页，看到作品卡就能直接进入
- 卡片默认简洁，额外反馈通过 hover 提供

## 4. 作品入口页设计

`/novels` 页面改为更像“项目入口页”，而不是单纯列表页。

结构：
- 顶部保留简洁页头
- 用更干净的作品卡承接所有项目

页头只保留：
- `作品库` 眼眉
- 一个简洁标题
- 一句极短辅助文案，可选

作品卡规则：
- 减少正文描述字数
- 元信息以更清晰的 pill 展示
- 视觉上强调“这是工作区入口”
- 保持整卡可点击

如果摘要过长：
- 截断显示
- 优先展示可帮助判断是否进入的内容，而不是完整介绍

## 5. 视觉系统调整

本轮不是纯样式润色，而是“视觉收敛 + 信息降噪”。

### 5.1 整体风格

方向：
- 更精简的编辑系统界面
- 弱化当前偏“纸张感”的视觉比重
- 保留一定温度，但整体更利落

### 5.2 背景与容器

要求：
- 背景保留轻层次，但更克制
- 减少同时竞争注意力的渐变、纹理和重面板感
- Hero 与作品区之间通过留白和节奏区分，而不是靠大量边框堆叠

### 5.3 字体与层级

要求：
- 标题更短、更有力度
- 正文层级更少，减少小段说明文本
- 通过字号、留白、字重建立清晰层级

### 5.4 卡片风格

要求：
- 状态卡更像产品状态而非说明卡
- 作品卡更像入口卡而非内容卡
- 边框、阴影、背景对比统一收敛，避免页面显得“块过多”

## 6. 交互与动效

动效原则：
- 只保留轻量进入动画和 hover 反馈
- 不使用炫技式大动画
- 动效为“建立秩序感”，不是“制造存在感”

具体表现：
- 首屏区块轻微上浮或淡入
- 按钮 hover 明确但克制
- 作品卡 hover 强化“可进入工作区”的信号

## 7. 响应式要求

移动端优先保证：
- 阅读顺序清晰
- CTA 在首屏可见
- 三个状态卡可单列堆叠
- 作品卡信息不拥挤

桌面端优先保证：
- Hero 信息在一屏内完成理解
- 作品入口在首屏下方尽快出现

## 8. 不在本轮范围

本轮不改：
- 小说工作区内部页面
- 章节编辑器
- AI 面板内部交互
- 数据结构与接口逻辑

本轮只处理：
- 首页 `/`
- 作品入口页 `/novels`
- 为这两页服务的全局样式收敛

## 9. 验证标准

改造完成后应满足：
- 用户打开首页 3 秒内知道这是 AI 协作写作产品
- 用户无需阅读长段文字就知道下一步点击哪里
- `进入示例工作区` 是最强入口，不被其他说明抢走注意力
- 页面整体更简洁，但不会空得像未完成页面
- `/novels` 页面比当前更像“项目入口页”，而不是简单数据清单

## 10. 实施建议

推荐实施顺序：
1. 重写首页模块结构
2. 重写 `/novels` 页头与列表卡片结构
3. 收敛 `globals.css` 中与这两页相关的视觉层级
4. 最后微调文案长度、留白和 hover 反馈

## 11. 风险与注意事项

- 如果保留过多现有文案，页面会重新回到“说明页”状态
- 如果过度裁剪文案但不强化入口层级，页面会显得空
- 如果视觉收敛只做减法、不补足层级，最终会变成“简单但不高级”

因此这轮的关键不是单纯删文字，而是：
- 删掉无关说明
- 把剩余信息排成清晰的用户决策路径
